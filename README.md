# AI Trade Analysis

Full-stack web app that turns **price data (CSV)** and/or a **chart screenshot** into a trade view:
signal, confidence, entry, stop-loss, targets, position size, risk analysis and a written explanation
generated by an LLM using a **Retrieval-Augmented Generation (RAG)** pipeline.

**Stack:** Python, Flask, HTML5, CSS3, JavaScript, MySQL (SQLite by default), REST APIs, AI/ML (pandas, scikit-learn, Pillow, LLM)

> Educational project. Output is not financial advice and no orders are placed.

## Features
- **Responsive web UI** (Flask + vanilla JS, dependency-free canvas chart, works offline)
- **REST API** for analysis, history, delete and knowledge-base Q&A
- **Image-processing workflow**: upload validation, secure file storage, candle-colour / foreground analysis to estimate trend slope, bullish-candle share, volatility and position in range
- **Data ingestion**: CSV loader with column-alias handling (date/open/high/low/close/volume), validation, SMA, EMA, RSI, MACD, Bollinger Bands, ATR, support/resistance
- **RAG pipeline**: knowledge-base ingestion (heading-based chunking of `knowledge_base/*.md`) -> TF-IDF retrieval -> retrieved chunks injected into the LLM prompt
- **LLM integration + prompt engineering**: Anthropic or OpenAI, structured JSON output, strict "use only these facts" system prompt. Falls back to an offline writer when no API key is set
- **Trade plan engine**: entry, ATR-based stop-loss, 1.5R / 3R targets, position size from your capital and risk %. Computed in code, never by the LLM, so numbers cannot be hallucinated
- **MySQL persistence** of every analysis (history, reload, delete)

## Architecture
```
Browser (HTML/CSS/JS)
   |  REST (JSON / multipart)
Flask app.py ──> services/indicators.py     (pandas indicators)
             ├─> services/image_analysis.py (Pillow + numpy chart reading)
             ├─> services/analyzer.py       (signal + trade plan + risk)
             ├─> services/rag.py            (chunk + TF-IDF retrieval over knowledge_base/)
             ├─> services/llm.py            (prompt, provider call, fallback)
             └─> db.py                      (MySQL or SQLite)
```

## Run it locally (VS Code)
```bash
# 1. open the folder in VS Code, then open the terminal (Ctrl+`)
python -m venv .venv
# Windows:  .venv\Scripts\activate        macOS/Linux:  source .venv/bin/activate
pip install -r requirements.txt
python app.py
```
Open http://127.0.0.1:5000 and click **Use sample data**. No API key or database setup is needed.

Run the tests: `python -m unittest discover -s tests -v`

## Optional: MySQL
1. Create the database: `mysql -u root -p < schema.sql`
2. Copy `.env.example` to `.env` and set `DATABASE_URL=mysql://root:yourpassword@localhost:3306/trade_ai`
3. Restart the app. The header badge will show `DB: mysql`.

## Optional: real LLM
Put `ANTHROPIC_API_KEY` (or `OPENAI_API_KEY`) in `.env`. The badge will show the provider and the
"Writer" chip on each result changes from *offline engine* to the model name.

## API
| Method | Route | Purpose |
|---|---|---|
| GET | `/api/health` | DB, LLM provider, KB size |
| POST | `/api/analyze` | form-data: `csv`, `chart`, `use_sample`, `symbol`, `timeframe`, `capital`, `risk_pct`, `price` |
| GET | `/api/analyses` | history |
| GET / DELETE | `/api/analyses/<id>` | load / delete one |
| POST | `/api/ask` | `{"question": "..."}` RAG Q&A |

CSV format: `date,open,high,low,close,volume` (only `close` is required, at least 50 rows). Try `sample_data/`.

## Limitations
- Image analysis is a classical computer-vision heuristic, not a trained model, so it is a supporting signal only
- Retrieval uses TF-IDF; swap in embeddings + a vector DB (FAISS/Chroma) to scale
- Indicators lag and fail in sideways markets. No backtesting yet

## Roadmap
Backtesting, live market data API, embedding-based retrieval, OCR of price axis from screenshots, user accounts.
